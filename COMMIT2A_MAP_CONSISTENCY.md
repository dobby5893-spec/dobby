The previous implementation independently took the latest 2D and 3D subscriptions, rejected results using a global 2D fingerprint, and had no source generation or 3D dependency validation. Manager acceptance used floor height and report time only; asynchronous stair searches had no identity linking them to the report that initiated them. This change preserves the completion classifications and algorithms, and changes only source pairing, evidence validity, reuse of unchanged map-dependent evidence, and the consumption/correlation of pending authority.

In src/go2_multifloor_exploration/src/floor_slice_node.cpp, mapCallback retains the immutable source message and increments octomap_generation for each accepted source. publishSlice captures that source and its generation together with the floor height, builds the existing slice without changing its algorithm, and increments floor_map_generation independently for each publication. Height-only changes therefore advance the floor generation without advancing the OctoMap generation. The original /map_floor output stays available. An additional /map_floor/snapshot transports FloorMapSnapshot, containing octomap_generation, floor_map_generation, source_octomap_generation, the exact original OctoMap message, and the resulting OccupancyGrid. Bundling the pair avoids assuming cross-topic ordering, timestamps, or subscriber callback counts establish provenance. It adds a full OctoMap payload per slice; its runtime bandwidth/memory overhead has not been benchmarked in Gazebo.

The new interface is defined in src/frontier_exploration_ros2/msg/FloorMapSnapshot.msg. src/frontier_exploration_ros2/CMakeLists.txt generates it with nav_msgs/octomap_msgs dependencies, exports the additional message dependency, and builds the new tests. src/go2_multifloor_exploration/CMakeLists.txt connects the slice producer to the interface, registers the new unit/ROS tests, and links their actual production dependencies. No default navigation, scoring, safety or timeout parameter was changed.

The new src/frontier_exploration_ros2/include/frontier_exploration_ros2/map_consistency.hpp defines MapVersion, PairedFloorMap, MapDependency and AuditMapEvidence. decodeFloorSnapshot checks valid nonzero generations and that the source generation matches the bundled OctoMap generation, then owns immutable floor/tree objects. Content digests do not use publication times. Evidence contains the producing generations and source/floor content digests, floor height/schema, boundary and margin, measured start XY, a complete in-boundary unknown-cell inventory fingerprint, and per-dependency 2D/3D hashes. Unknown-inventory changes cannot silently disappear behind an unchanged existing region. Regional floor hashes also include reachable-candidate membership, so a remote bridge closing/opening can invalidate a dependent region even when nearby occupancy has not changed. Regional 3D hashes include both free and occupied leaves, their keys/depths and resolution, and include intersecting pruned leaves. Conservative vertical columns cover support, body clearance, sensor rays and upper-level occluders. No unknown cell is relabelled or edited.

In src/frontier_exploration_ros2/include/frontier_exploration_ros2/residual_region_audit.hpp, ResidualRegion retains its exact unknown-cell membership. ResidualAudit retains map evidence and support context. sealResidualAudit records each region's observation envelope using the existing 4m candidate search and body/sensor/snap margins. It also records the start neighbourhood used by the existing 4m support-plane fitting. Unfinished or negative route searches conservatively retain broader dependencies. canReuseOccludedRegion only reuses a prior region's completed 3D occlusion evidence when its membership, schema, generations, support/sensor context, transition/runtime evidence and relevant 2D/3D dependencies still agree. It never promotes failed navigation, deferred validation or no-gain evidence. ResidualAuditStability uses dependency/inventory fingerprints rather than unrelated global 2D changes; the existing requirement of three fresh samples over ten seconds is unchanged. ResidualAudit::status, BLOCKED/no_route/no_known_access rules, visibility tests, ray checks, SurfaceGraph checks and safety thresholds are unchanged.

In src/frontier_exploration_ros2/include/frontier_exploration_ros2/frontier_explorer_node.hpp and src/frontier_exploration_ros2/src/frontier_explorer_node.cpp, the snapshot subscription follows the configured map_topic plus /snapshot. serviceResidualAudit requires the corresponding legacy floor content to agree, and captures the exact immutable pair, config/sensor, boundary, runtime evidence, transition mask, epoch and measured pose into the worker. On return it revalidates source generations, schema/height, unknown inventory, regional 2D/3D dependencies, current live OctoMap dependencies, runtime/transition evidence, epoch and the existing pose-drift limit. Related changes discard the stale result. Unrelated changes retain evidence and can reuse unaffected completed regions, including across an otherwise invalidated aggregate audit. Stable authority also requires pairedSourceCaughtUp: a newer unpaired 3D semantic update must first be accounted for by its matching floor slice. This is a publication gate, not a reason to erase regional caches or weaken verification. The existing /explore/floor_completion String gains additive map_evidence metadata via encodeMapEvidence; it is not v5 and has no floor_session_id. The original v4 diagnostic still publishes with its existing meaning.

In src/go2_multifloor_exploration/src/multifloor_manager.cpp, the subscription calls acceptFloorCompletion, which requires the existing verified parser/floor/time checks plus valid map evidence and matching evidence/report floor heights. PendingHandoff retains the specific wire report, immutable evidence and a monotonically increasing process-local request_id. An identical pending wire message does not replace that request. pendingHandoffValid revalidates the authority against current paired and live maps rather than trusting reception-time validation. launchSearch captures the exact pending request ID, its evidence, the paired source tree and slice, plus the source tree's semantic hash. collectSearch rejects a result whose request ID no longer matches, whose map evidence changed, or whose source tree changed, before remembering candidates or publishing a transition footprint. Matching selected routes keep the pending report until tick revalidates it again immediately before STOPPING_FRONTIER; this includes the last configured floor's no-stair path. Newer unpaired unrelated 3D data holds authority until the slice catches up, while related changes invalidate it. The existing EXPLORE_FLOOR-only acceptance and stop/idle/service guards remain. Stair detection, route algorithms, gait commands, landing validation and all motion parameters remain unchanged. Stair search results conservatively invalidate on whole-source semantic change, rather than asserting an unsupported local negative-route dependency.
